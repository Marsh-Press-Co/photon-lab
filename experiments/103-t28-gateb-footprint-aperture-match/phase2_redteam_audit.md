## 1. My own findings (not raised by any of the five)

**1. [inconsistency] — `edge=80` is the wrong constant for Gate B's own grid resolution; it is calibrated for a *different* cells-per-lambda than Gate B runs at.**
Traced the actual provenance: `design_geometry.py` (exp-069) sets `R4_RATIO = 2.0`, `R4_CPL = {600: 40}`, and `R4_TAPER = round(TAPER * R4_RATIO)` where `TAPER = 40` is defined in exp-065's `design_geometry.py` for a **cpl=20** base grid. `R4_TAPER = round(40*2.0) = 80` is deliberately scaled *up* by the R4-family's own 2x resolution increase so that the taper occupies the same **physical width in wavelengths** (2λ) at cpl=40 as `TAPER=40` occupies at cpl=20. Gate B's own grid (this proposal's Parameter table: `cells_per_lambda = 20`) is the **cpl=20 base grid `TAPER` was originally defined for** — not the cpl=40 R4-family grid `R4_TAPER` was rescaled for. Reusing `edge=80` unchanged at cpl=20 gives a taper occupying **4λ**, twice the physical width the R4-family aperture actually represents, not "the R4-family aperture" at all.
This is not a hypothetical — it is the *exact same bug class* the proposal itself narrates fixing for `D_STANDOFF`/`H_REGION`: exp-102's own code (lines ~283–318) explicitly rescales those by the article's `r_out` ratio specifically *because* "reusing [them] UNCHANGED IN CELL COUNT at this coarser grid does NOT hold the same physical... ratio" between the cpl=20 Gate-B grid and the cpl=40 R4-family grid. The proposal applies that lesson to `D_STANDOFF`/`H_REGION` (inherited, correctly) but never asks the identical question of `edge` — the one parameter it is *actively changing this cycle*. If the intent (stated repeatedly: "matching the R4-family aperture," "R4-family aperture (edge=80)") is physical-taper-width fidelity, the correct value at cpl=20 is `TAPER=40`, not `R4_TAPER=80`. If the intent is literally "same cell count regardless of physical width," that is a defensible but different claim that the proposal never states or defends — and it would reintroduce, one level down, precisely the "aperture confound smuggled in via an unexamined cross-scale constant" failure this whole cycle exists to eliminate.
**This is the single highest-priority item in the docket** — a one-line parameter question, but it goes to the cycle's entire stated purpose.

**2. [process/rigor finding, R19] — the "exactly 2 calls / 11 readings" claim is prose, not yet a code-enforced assert.**
R19 requires an *explicit, checkable, CODE-ENFORCED assert* distinguishing FDTD-call-count from row/data-point-count "wherever both exist in the same computation — never a reviewer's manual cross-check." This proposal's own Section 2 states exactly the shape R19 was written to police (2 calls, 11+1 reported readings) — it does not currently conflate them (no violation), but nothing in the Phase-1 document commits to the code-enforced form. exp-102, this cycle's own direct predecessor and same instrument family, already demonstrates the required pattern verbatim: `assert len(jobs) == 24` and `assert len(rows) == 12`. Phase-4 build must include the equivalent (`assert n_fdtd_calls == 2`, `assert len(kappa_region_readings) == 11`) — not asserted by this document, so not yet discharged.

**3. [inconsistency] — the Prediction (iii) floor-gate reference ("FLOOR_FRAC(0.10) of the source-region reference amplitude") departs from this program's own established floor-gate convention without disclosure.**
Traced exp-102's own `floor_gate()` (the "R13/R14 lineage, house style" gate this proposal explicitly claims to reuse): it computes the RMS **across the pool of the actual local denominator readings themselves** (`i_region_empty` at each of the 12 sampled points) and floors each point against `FLOOR_FRAC * that pool's own RMS` — a locally-grounded, per-point-relative gate, which is what discharges R13/R14's requirement that the *denominator's own local magnitude* be checked, not a proxy. "The source-region reference amplitude" (singular, proposal's wording) reads as a *different, fixed, global* quantity (e.g. measured at/near `SRC_X`) rather than the RMS of the 11 points' own local empty-scene readings. If a fixed global reference is what's meant, it is a **weaker** gate than established convention — it cannot catch a genuine local near-field diffraction dip in the empty-scene denominator at one particular standoff x, which is exactly the R13 hazard (a ratio's denominator sourced from a field known to carry spatial structure). Per R17, any tolerance/gate construction departing from established precedent needs justification against that precedent, not silent restatement in looser language. Needs one sentence pinning the floor gate to the exp-102 formula exactly, or an explicit, justified departure.

**4. [process/rigor finding] — `beam_behind` (envelope(), uncorrected two-snapshot Pythagorean sum) and `kappa_window` (phasors(), trig-corrected quadrature) are not as interchangeable as PHOTONICS's steel-man claims, and the gap is quantifiable and non-trivial at this exact configuration.**
`envelope()` computes `sqrt(snap_a**2+snap_b**2)` directly from two raw snapshots offset by `quarter = round(lam/S/4)` steps — exact only if that offset lands at *precisely* a quarter period (`phi = omega*offset = pi/2`, so `cos(phi)=0`). `phasors()`/`_phasor()` uses the same offset but applies the exact trig correction (`cos(phi)/sin(phi)`) regardless of how close `phi` lands to `pi/2` — this is explicitly the fix `_phasor()`'s own docstring describes as closing the stage-6/stage-8 "camera floor" quantization bug (`lab/emit.py`), i.e. the exact "FFT wavelength quantization" lesson `VALIDATION.md`/`CLAUDE.md` name as paid-for. At this cycle's own numbers (`lam=20` cells, `S = 0.32/sqrt(2) ≈ 0.2263`, `quarter = round(22.10) = 22`, `omega ≈ 0.07111`), `phi ≈ 1.5644` rad vs. exact `pi/2 = 1.5708` — a `cos(phi) ≈ 0.0064` residual. Propagating that through `sqrt(Re²+(Re·cosφ+Im·sinφ)²)` gives `envelope()` a possible relative bias up to roughly `2·0.0064·Re·Im/|F|²`, i.e. **up to ~0.6% in the worst phase relationship** — not negligible against the proposal's own predicted band floor of 0.5%. `kappa_window` is bias-free by construction (same offset, trig-corrected); `beam_behind` is not. This doesn't kill the anchor comparison, but PHOTONICS's "stronger apples-to-apples footing than the... hedge claims" overstates it: these are two different amplitude-reconstruction techniques with different, uncorrected-vs-corrected quantization behavior, and the mismatch is directly a candidate explanation if kappa_window lands outside the predicted band on the low side. Worth one disclosure sentence; does not block Phase 4.

## 2. Ruling on each of the five blind critiques

**PHOTONICS (support-with-changes) — ADOPT.**
The Nyquist argument is correct and cleanly derived: 6 window-spanning points at 18–21 cell pitch against a `cpl=20` grid is ~1λ sampling of a field that a partially-reflective shell can imprint with λ/2-scale standing-wave structure — textbook sub-Nyquist aliasing risk for exactly the monotonicity claim Prediction (ii) needs. The steel-man's phasor-equivalence claim is directionally right but overstated (see finding 4 above) — I adopt the attack, not the steel-man's strongest framing of it. **Fix adopted**: tighten the window-spanning pitch to ≤10 cells (λ/2) across [357,457), or (cheaper, zero new FDTD calls since the field is already captured) report each window's internal spatial min/max/variance alongside the mean so a reader can see whether "smooth fill-in" or "averaged fringes" produced the number. The second option is strictly cheaper and should be the default; the first only if the standoff-trend claim (ii) specifically needs point-level resolution.

**ELECTROMAGNETISM (support-with-changes) — ADOPT-WITH-MODIFICATION (the diagnosis is overclaimed, the remedy is still worth taking cheaply).**
Verified `graded_black_shell`'s default `sigma_max=0.5` (confirmed: Gate B's own construction never overrides it) — this is **exactly** the "moderately-lossy canonical bench (sigma_max=0.5)" `VALIDATION.md`'s stage-20 entry says settles to ~1.5e-5 field-relative RMS by 900 steps, not the "~10,000x less lossy" near-null-tau geometry the cited "~100x larger residual" figure was actually measured on. Gate B runs STEPS=3200 — already >3.5x the step count validated sufficient for this exact loss level. The critique's own headline number ("~100x larger... carry its OWN empirical noise-floor validation leg") is imported from a structurally different regime (a *phase-rotation* reconstruction on a *near-lossless* article) and doesn't transfer cleanly to Gate B's ordinary two-snapshot quadrature phasor on a moderately-lossy article — the alarm is overstated as cited. That said: x=352 was already implicitly probed at this identical STEPS/geometry in exp-102's own Phase-4 rescaled-Gate-B check (kappa_region~0.16% there), giving *some* existing precedent that nothing catastrophic happens at this standoff/step count — but x=353–356 are genuinely new. **Fix adopted, scaled down**: not a mandatory 2x-STEPS full rerun of all 5 gap-fill points (that would silently blow the "exactly 2 calls" budget into 4+ and needs to be reconciled with finding 2 above if taken) — instead, one cheap settling spot-check at a single representative gap-fill x (e.g. x=354) at 2x STEPS, reported as a footnote leg, sufficient to confirm the sigma_max=0.5 precedent actually holds here before the monotonicity claim leans on all 5 points. If the Director wants the full ELECTROMAGNETISM-strength fix instead, the call-budget line in Section 2 must be rewritten accordingly — cannot silently coexist with "exactly 2 calls."

**THERMODYNAMICS (support-with-changes) — ADOPT.**
Verified independently: `thermo_sidecar`'s dependency chain (`p_abs_w ← sigma_ext_cells [exp-059 Mie/qext] × assumed i_incident_w_cm2`) genuinely never reads Gate B's own FDTD source construction or `edge`. The critique's own point stands regardless: "not touched" asserted by precedent-matching is weaker than "not touched, and here is the dependency chain proving why." Cheap, zero-cost, directly forecloses a future citation-independence question. One sentence, as proposed.

**QUANTUM OPTICS (support-with-changes) — PARTIALLY OVERRIDE, explicit ruling on the PHOTONICS-vs-QUANTUM question below.**
The critique's own note candidly flags its uncertainty, and on inspection the uncertainty resolves cleanly: `_phasor()`'s magnitude is provably invariant to `rel_phase` (§0). **The specific proposed remedy — sample each of the 11 x-points at 3–4 phase references and report envelope+spread — is OVERRIDDEN, not merely downgraded.** As specified it would not average anything: re-running at different `rel_phase` multiplies the *entire* complex field by a common unit-modulus factor, leaving `|Ez|` (and hence `kappa`) at every point bit-for-bit unchanged. It would burn 3–4x the FDTD call budget (directly violating the "exactly 2 calls" line, worse than ELECTROMAGNETISM's fix) for a measurement with **zero** information content — a "phase-averaged" version of a quantity that is already phase-invariant.

**Explicit ruling on the PHOTONICS/QUANTUM relationship, as the audit note requests: these are the SAME underlying finding under two framings, and PHOTONICS's is the technically correct one.** Both seats are worried about the same thing — coherent spatial ripple under-sampled by the standoff grid — but QUANTUM's causal story (single fixed launch phase) is wrong, while PHOTONICS's (λ/2-scale standing-wave structure vs. ~1λ sampling pitch, a spatial Nyquist argument) is the mechanistically correct description of the identical worry. Ruling: **adopt PHOTONICS's fix (tighter spatial pitch or reported window variance) as the sole discharge of this concern; QUANTUM's own remedy is fully superseded and must not additionally be implemented** — doing both would waste FDTD budget on a no-op. QUANTUM's broader "T25/T26 hazard, applied to a different channel" framing and its FLOOR_FRAC/pre-registration observations are otherwise sound and require no separate fix.

**VISION SCIENCE (support) — ADOPT.**
Directly on point for this cycle's own explicit constraint-3-drift risk (Checkpoint criterion 4: "program-integrity drift... a constraint quietly dropped — especially constraint 3"). Confirmed by direct read: Section 1's "how this idealized simulated article's own near-field shadow fills in" and Section 6's "less smoothness," "higher near-field floor," "should sit at or above" are everyday-visual vocabulary with no adjoining disclaimer, unlike exp-102's own precedent (an explicit perceptual-overclaim strike is on file for this instrument family already, per this critique). This is the cheapest fix in the whole docket (one sentence) against the one target constraint Red Team is chartered to protect hardest. No reason to override any part of it.
