## 4. Additional notes (not word-capped)

**Mandatory fix, not optional:** Phase 4's `run.py` must include a hard assert, not a docstring promise — e.g. after both report dicts (item i's 24 rows, item ii's 8 rows) are built: `NETD_KEYS = {"p_abs_w_c","p_abs_w_g","dt_ss_full_K_c","dt_ss_full_K_g","netd_classification_c","netd_classification_g","sigma_ext_cells_c","sigma_ext_cells_g","ratio_abs_ext_raw_c","ratio_abs_ext_raw_g"}` then `assert all(NETD_KEYS <= row.keys() for row in all_32_rows)` before `results.json` is written, raising (not warning) on any gap. Given the standing forward-elevating clause is live this exact cycle, a design constraint that only "Phase 2/3 can hold as a mandatory fix if omitted" is reactive review, the same shape that already failed once under this same R4/C40/G40 pairing — this cycle needs the stronger, build-failing form.

**On the padded (G40_*) legs specifically:** `netd_row()` itself is not leg-selective — it reads whatever `pair_metrics_full` already threaded from both `c_cell` and `g_cell` (`_c`/`_g` suffixed keys), so *if* the assert above passes, both legs are covered by construction, not by hope. But item (iv)-d's own restated Idealization flags that Check 5 (the registration gate) has never independently verified any `G40_*` construction — a different, already-disclosed gap, not this one. Worth stating explicitly in Phase 4's writeup that "Check 5 never tested G40_*" and "netd_row() covers G40_* cells" are two independent claims so a future audit doesn't conflate registration-gate coverage with sidecar-persistence coverage.

**On GP1 and the absorbed-power ledger:** GP1's bound (`C(θ) ≥ −1`, "no gain anywhere in this construction") is correctly self-contained as stated — it is a scattering/diffraction-*amplitude* passivity bound on a closed-form, lossless, source-driven field superposition (`edge_diffraction_c_empty_corrected`), with no absorbing article and no `thermo`/`p_abs_w` channel anywhere in that calculation. It should **not** be cross-checked against this program's own absorbed-power ledger, because there is nothing on that ledger to compare against here — doing so would be a category error (conflating "no negative-flux amplitude artifact" with "power in = power absorbed + power scattered," a claim that requires an actual absorbing medium, which this leg does not model). The one thing I'd add, non-blocking: a one-line disclaimer in the GP1 write-up stating exactly this — that GP1 is an amplitude-passivity check, not an energy-conservation check, and is silent on absorbed power — so a future reader doesn't read "passivity confirmed" as "energy budget closes." This costs zero FDTD and zero new computation, just one sentence.
