## 1. What I checked on T2-1 (my own charter duty)

The mandate states T2-1 is VISION's "reinstated" condition. What I actually specified at exp-072 §7 was: **`RESOLVED` additionally requires `sign(ΔP)` invariant across the *fixed, unconditional* three-carrier set `{T_mean, T_delta, 1.9608°}`** — all three already inside the existing consistency band, no exclusion mechanism, and I ran it on the real data: every one of the four pairs flips sign somewhere in that band, so the condition as I wrote it forces NEITHER across the board.

exp-073's actual implementation (§3b, P-073-2 clause vi) is materially different: sign(ΔP) must agree with T_mean only over members of `{T_delta, T_wrong=1.2591°}` that **independently pass "clause (iv) at its own carrier" first** — carriers failing that gate are dropped from the test, not counted against it. Two concrete problems, found by reading the document, not by running it:

**(a) The gate that decides exclusion is never specified.** §3b cites "§5 G-gate table" as the source of the per-carrier admissibility gate. §5, as written, is titled "Named-constant / parameter search — R5 applicability" and contains no gate table of any kind — I grepped the full document for "G-gate," "clause (iv)," and "its own carrier" and confirmed there is exactly one definition of a carrier-consistency statistic anywhere (P-073-2 clause iv itself, `|T_delta−T_mean|/T_mean ≤ q₉₅`), written for `T_delta` specifically. Whatever "clause (iv) at its own carrier" means for `1.2591°` is undefined in this document. A gate that decides which carriers count toward the flagship new safeguard cannot be verified fair, lenient, or even well-formed when it isn't written down.

**(b) The natural reading creates a structural tension with the wrong-carrier's own design.** If "clause (iv) at its own carrier" means the obvious substitution — `|1.2591°−T_mean|/T_mean ≤ q₉₅` — then admission is a *closeness* test. But §3a's entire justification for choosing `1.2591°` is that it is the **leakage-minimizing, maximally-displaced** comparator inside `[1°,4°]`: "≥2.36 Rayleigh widths of displacement," chosen specifically to be as unlike `T_mean` as the search range allows. Using the exp-072 `T_mean` values I already published (public record, not new computation — `2.4865/2.5285/2.5325/2.4905`), `|1.2591−T_mean|/T_mean` = 0.494/0.502/0.503/0.494 at the four pairs — roughly 20% farther, in relative terms, than the old fixed 0.414 Rayleigh bound exp-072 used for the *same* formula applied to `T_delta`. If `q₉₅` (now data-calibrated, replacing that fixed 0.414) lands anywhere near its predecessor's order of magnitude, the carrier engineered to be furthest from `T_mean` is also the carrier most likely to be **excluded from the set that is supposed to test agreement with it** — deterministically, by construction, not because the data earned an exclusion. That leaves T2-1, in the case that matters most, testing agreement with `T_delta` alone: one carrier, not three, and specifically the one I did *not* find flipping sign as dramatically in my exp-072 check on the old wrong-carrier (`1.9608°`, now dropped from the required set entirely, kept only as non-gating disclosure per §3a/P-073-5). *(I did not compute the real `q₉₅` — that requires bootstrapping the real 5-column residual, which is outcome-determining for this exact gate; I have not done so and flag that explicitly.)*

Nothing here required running the estimator on the real 124 points. Both findings are readable from the document as submitted.

## 3. Sharpest attack (≤150 words)

T2-1 is credited to my seat but is not the test I specified. My version was an unconditional three-carrier agreement check that, run on the real data, failed every pair. exp-073's version adds a data-dependent exclusion clause whose gate is never actually defined — §3b cites a "§5 G-gate table" that does not exist anywhere in this document — and whose only literal antecedent (clause iv's `T_delta`-vs-`T_mean` formula) creates a structural tension when applied to `1.2591°`: that carrier was deliberately chosen to be *maximally displaced* from `T_mean` (≥2.36 Rayleigh widths, by design), which is close to the opposite property a closeness-based admissibility gate would demand. Using already-published exp-072 `T_mean` values, `1.2591°` sits ~0.49–0.50 relative distance away — comfortably past exp-072's old fixed 0.414 bound for the identical formula. If the new gate behaves similarly, the carrier engineered to catch a spurious sign flip is excluded from the sign-invariance test by construction, not by evidence, leaving T2-1 to check agreement with `T_delta` alone — a materially weaker test than the one that, on the real data, I already showed fails everywhere.

## 4. Verdict: **support-with-changes**

The design is not unfair by intent — every named change is data-free-justified, and most tighten rather than loosen the prior cycle's bars. But the one piece of machinery I am specifically asked to certify (T2-1) is currently unimplementable as written (missing table) and, under its most natural completion, carries a real risk of collapsing to a single-carrier test exactly where a real spurious effect would most need the excluded carrier to catch it. This is a documentation-and-specification gap, not a physics or statistics defect, and is fixable without touching FDTD or the rest of the design.

## 5. Optional: the single change that would flip my verdict to support

Replace clause (vi) with an explicit, self-contained definition — no forward reference — of two things, fixed before any real pair is fit: (1) the exact per-carrier admissibility statistic for `1.2591°` (if it is `|1.2591°−T_mean|/T_mean ≤ q₉₅`, state so and report `q₉₅`'s value from `G0-e`'s own synthetic calibration, not the real-data null, so the bound is known before real data is touched); and (2) a floor requiring the admitted non-`T_mean` set to be **non-empty** for `RESOLVED` to be reachable at all — i.e., if both `T_delta` and `1.2591°` are excluded, the pair is `NOT_EVALUABLE` for T2-1, not vacuously passed. That single non-emptiness clause closes the loophole regardless of how lenient or strict `q₉₅` turns out to be.
